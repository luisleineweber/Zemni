Zemni · product improvement guide

Make the study workflow trustworthy enough to ship.

A sequenced implementation plan based on the full product review. Close security and release blockers first, then make the core workflow accessible and easier to understand.

Three blockers to remove first

These items should interrupt normal feature work.

P0 · SECURITY

Lock down Notion export

The route accepts a request token and can fall back to a global token without enforcing authentication.

P1 · AI TRUST

Restore the instruction/data boundary

Refine content is inserted into the system prompt and caller-supplied system messages are still accepted.

P1 · RELEASE

Make CI prove the app works

Typecheck, tests, build, lint, and browser access do not currently provide a reliable green signal.

Recommended sequence

Work in this order so later improvements rest on a trustworthy baseline.

PHASE 0 · NOW

Contain risk

Protect credentials and stop unbounded AI/billing behavior.

  • Notion auth and tokens
  • Refine prompt boundary
  • Fail-closed quotas
PHASE 1 · NEXT

Restore proof

Turn the repo into a dependable release candidate.

  • Fix generated/source drift
  • Align tests and exports
  • Add deterministic lint
PHASE 2 · BEFORE LAUNCH

Make it usable by everyone

Remove barriers in upload, history, generation, and output.

  • Keyboard semantics
  • Focus and live regions
  • Mobile verification
PHASE 3 · AFTER

Improve activation

Increase comprehension and repeat usage once safe.

  • First-run guidance
  • Language strategy
  • Output trust signals

P0

Secure Notion export

API · Convex

Make export user-scoped instead of a general-purpose Notion write proxy.

Open execution guide

Change

  • Require Clerk auth at route entry.
  • Remove body.notionToken as a credential.
  • Decrypt only the authenticated user's token from Convex.
  • Restrict env-token use to an explicit server-owned target.

Evidence / done when

  • app/api/notion/export/route.ts:20
  • Unauthenticated export returns 401.
  • Cross-user token use is impossible.
  • Tests cover auth, token lookup, target validation, and streaming.
